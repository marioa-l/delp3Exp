DeLP3E SAMPLER RECOMMENDATION - FINAL RESULTS

Ground truth: both samplers run until one reaches the exact interval;
the winner is whichever gets there first. This does not depend on a
chosen timeout, unlike 'best interval within N seconds'.

  TRADE-OFF worth stating out loud: the comparison tree has the best
  accuracy but the WORSE minority recall (0.60 vs 0.84). It gets there
  by leaning to the majority class - it never misses a 'worlds' case
  (recall 1.00) but misses 40% of the 'programs' ones. If the cost of
  running the wrong sampler is symmetric, the binned tree is the
  better choice despite the lower headline accuracy.

-- The tree to present --
  Every question compares two attributes; no numeric thresholds.
  Questions whose two answers give the same recommendation were
  removed (3 questions / 4 leaves -> 2 questions / 3 leaves), which
  changes no answer at all.

      IF am_n_arguments < em_n_arcs:
          IF em_entropy < n_annots:  -> WORLDS   (n=519,  purity 85%)
          ELSE:                      -> PROGRAMS (n=127,  purity 98%)
      ELSE:                          -> WORLDS   (n=1244, purity 100%)

  Leave-one-config-out (weighted): 0.8286 - below the 0.8926 baseline,
  so the tree does NOT transfer to a configuration it never saw. It
  is validated for unseen models within known configurations only.

-- Attribute cost, and what it buys --
  How each attribute is obtained, cheapest first:
    tier 0  read straight off the model JSON (n_annots, n_rules, em_var, af_*)
    tier 1  graph metrics over the BN DAG    (em_n_arcs, em_closeness_*, ...)
    tier 2  BN inference / NP-hard           (em_entropy, em_treewidth)
    tier 3  runs the DeLP solver             (am_* , incl. am_n_arguments)

  Tier 3 is the expensive one: it launches the solver as a subprocess with a
  900 s timeout — the very work the recommendation exists to avoid. Note the
  first tree put am_n_arguments at the ROOT, so every query paid for it.

  Tree variants (all validated the same way, GroupKFold by model):

    attributes allowed          accuracy            structure
    everything                  0.9550 +/- 0.0116   2 questions / 3 leaves
    no DeLP solver              0.9524 +/- 0.0157   2 questions / 3 leaves
    no BN inference             0.9360 +/- 0.0184   6 questions / 7 leaves
    neither (tiers 0-1 only)    0.9413 +/- 0.0271   5 questions / 6 leaves

  Dropping the solver costs almost nothing (0.9550 -> 0.9524): em_n_arcs
  replaces am_n_arguments at the root and still splits 1190 queries at 100%
  purity. Dropping entropy as well costs about 1.4 points and buys a richer
  tree. The all-cheap tree is the one now saved as final_tree.pdf.

  Caveat on that tree: its smallest leaf (n=77) sits at 55% purity, barely
  better than a coin flip. The extra depth is not all signal.

-- Heuristics (separate experiment, 678 queries, 300 s cap, paired) --
  Adding a heuristic to the recommended method does NOT help overall:
  median delta -0.000, heuristic wins 39.4% of queries.
  Only one leaf improves (median +0.769, 100% wins); one degrades
  badly (-0.694, 0% wins); the rest are neutral to slightly negative.
  It also reaches the exact interval far less often: 456 -> 257.
  Intervals stay sound: 0/678 failed to contain the exact interval.
